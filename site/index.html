COAL

COAL makes codon alignments. Give it a protein alignment and the coding DNA of the same genes, and it writes the DNA back under the protein, three bases to a residue, with a gap of three wherever the protein has a gap. It checks every codon against its amino acid as it goes, and when a gene does not fit it says which gene, at which column, and what is probably wrong.

It does the job of PAL2NAL v14, with the same input files and options and the same output apart from a few documented differences, and it is a good deal quicker on large data: a million genes of 400 codons took 12.5 s with COAL's C++ engine and 62 min with PAL2NAL v14 on the same machine. There is a Windows app, a command line for pipelines, and a Python package. MIT licence.

Download

Version 0.4.2. Release notes and older versions.

Windows 10 and 11

COAL-Setup-windows-x64.exe, the installer (64-bit). It installs for your user account and needs no administrator rights. It is not code-signed, so Windows asks you to confirm before it runs; the install page shows the two screens. The C++ engine is included.

Without an installer: COAL-windows-x64.zip, unzip and run COAL\COAL.exe.

macOS and Linux

With Python 3.10 or newer, in a terminal:

python3 -m venv ~/coal-env ~/coal-env/bin/python -m pip install "coal-align @ https://github.com/plumat-coal/COAL/releases/latest/download/coal_src.tar.gz" "coal-align-app[gui] @ https://github.com/plumat-coal/COAL/releases/latest/download/coal_app_src.tar.gz" ~/coal-env/bin/coal-gui

This makes a virtual environment in ~/coal-env, installs the engine (coal-align) and the app (coal-align-app) into it, and starts the app in your browser. Step by step: macOS, Linux, command line. COAL is not on PyPI; pip install coal is a different package.

Source

coal_src.tar.gz (the engine) and coal_app_src.tar.gz (the app), or the repository on GitHub. SHA256SUMS.txt covers every file; how to check one.

What it looks like

In the repository's one_broken_gene example, one of 20 genes is missing a base. On the command line, COAL stops, names the gene and the column, and writes nothing:

$ coal examples/one_broken_gene/protein.aln.fasta examples/one_broken_gene/dna.fasta -o codon.aln.fasta
coal: error: OG0001_sp14: protein and DNA are inconsistent (no match found)
coal: summary: OG0001_sp14: Frameshift at column 102: one base is missing in the DNA, so from here on the codons are read out of step.
coal: summary: The run stopped at OG0001_sp14: 6 sequences were not checked and no output was written. Add --keep-going to write the other sequences and leave this one out.
$ echo $?
1

The guide has more examples, and what each warning means.

Why use it

  • A PAL2NAL command line works as it is: the pal2nal command takes the same options and writes the same output. Our tests compare COAL with stored PAL2NAL v14 output in 285 checks.
  • A gene that does not fit is an error, with exit status 1 and the gene and column named. PAL2NAL v14 prints a note and exits with 0, so a pipeline carries on with a bad alignment.
  • Large inputs finish. A million genes took 18.6 GB of memory with PAL2NAL v14 and 172 MB with COAL.
  • Mitochondrial and other genetic codes use the current NCBI tables, and when the genes fit another code better, COAL says which.

The C++ engine

COAL has two engines that give byte-identical output. The Python engine installs anywhere with pip. The C++ engine, coal-cpp, is the fast one on large data. The Windows app includes it and uses it on its own for inputs of 1 MB or more. With a pip install, build it from the source; you need a C++17 compiler and CMake 3.16 or newer:

git clone https://github.com/plumat-coal/COAL && cd COAL
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build --config Release
export COAL_CPP=$PWD/build/coal-cpp

coal then hands large inputs to coal-cpp, and coal-cpp itself takes the same options as coal. Details in the guide.
