COAL

COAL makes a codon alignment from a protein multiple sequence alignment and the matching coding DNA.

It is a drop-in replacement for PAL2NAL v14: it accepts the same input files and options, with the exceptions listed under Limitations. Its warnings and errors name the gene concerned.

Version 0.4.0 · MIT licence · Release notes

Windows

Download Windows installer

64-bit Windows 10 and 11. Installs for your user account, without administrator rights. It is not code-signed yet, so Windows asks you to confirm before it runs (what to expect).

Example

The repository's clean example has 8 genes of 140 to 144 codons (plus a stop codon), aligned in 150 columns, with gaps in the protein alignment only.

$ coal examples/clean/protein.aln.fasta examples/clean/dna.fasta -o codon.aln.fasta
$ echo $?
0
$ head -3 codon.aln.fasta
>gene01
ATG---GCGAGG---CCTTCCACTACTACCGTGAATATGTGGGGCTCGACACCAGTTTGG
AATGGAGGG---AAAATG---TGGTTTGCTATGGGCGCCGTTGATAATATGCCTACCATG

PAL2NAL-style options work as they are, for example coal pep.aln nuc.fasta -codontable 2 -o out.fasta. The package also installs a pal2nal command that takes a PAL2NAL command line unchanged. With -nogap, COAL removes the stop codons of the genetic code you chose; PAL2NAL v14 always removes the standard code's.

Large inputs are split across processes automatically. -j sets the maximum.

Warnings and errors

The mito example has 24 vertebrate mitochondrial genes. With the standard genetic code (the default), COAL writes the alignment but warns about every codon that does not match its residue, then suggests a code:

$ coal examples/mito/protein.aln.fasta examples/mito/dna.fasta -o codon.aln.fasta
coal: warning: Homo_COX1 pepAlnPos 1: M does not correspond to ATA
coal: warning: Homo_COX1 pepAlnPos 7: M does not correspond to ATA
coal: warning: Homo_COX1 pepAlnPos 36: W does not correspond to TGA
(176 more warnings, 179 in all)
coal: summary: 24 of 24 sequences have codons that do not match their amino acid (kept in the alignment). Under genetic code 2 (Vertebrate mitochondrial), all 24 sequences match their protein; under code 1, none do. Codes 5 and 13 fit these sequences too: choose the code of the organism and organelle the genes come from. Re-run with code 2?
$ coal examples/mito/protein.aln.fasta examples/mito/dna.fasta -codontable 2 -o codon.aln.fasta
$

The desktop app runs the same engine and gives one line per gene instead of one per codon:

Homo_COX1: 7 codons do not match their amino acid (first at column 1): the protein says M but the DNA has ATA. Kept in the alignment; check the genetic code.

In the one_broken_gene example, 1 of 20 genes is missing a base. The run stops and nothing is written:

$ coal examples/one_broken_gene/protein.aln.fasta examples/one_broken_gene/dna.fasta -o codon.aln.fasta
coal: error: OG0001_sp14: protein and DNA are inconsistent (no match found)
coal: summary: 1 sequence of 20 could not be converted (first: OG0001_sp14: protein and DNA are inconsistent (no match found). Frameshift at column 102: one base is missing in the DNA, so from here on the codons are read out of step.)
coal: summary: The run stopped there: 6 sequences were not checked and no output was written.
$ echo $?
1

PAL2NAL v14 reports an inconsistency here too, but exits with status 0, so a pipeline would carry on.

Not every frameshift stops the run. A base missing near the end of a gene can still let the gene fit, with a few mismatch warnings; the app then says the run of mismatches looks like a frameshift.

Differences from PAL2NAL

PAL2NAL is by Suyama, Torrents and Bork (2006). We wrote COAL independently, in Python, and it contains none of PAL2NAL's code: we ran PAL2NAL version 14 as a separate program, only to compare outputs. PAL2NAL is GPL-2.0; COAL is MIT.

COAL's output is identical to PAL2NAL v14's except for a short list of documented, deliberate differences. These are newer NCBI genetic-code tables (codes 3, 10, 11 and 13), -nogap removing the chosen code's stop codons, the chosen code's start codons for the first Met, pairing by IDs that match only after normalising, and inputs where PAL2NAL v14 writes malformed output or fails.

Our test suite compares COAL with stored PAL2NAL v14 output on 39 input cases, with every option combination in all 4 output formats: 285 checks.

  • Standard output is byte-identical in 238 checks. In 4 of these the warnings differ on purpose (NCBI tables 10, 11 and 13).
  • Of the rest, in 24 both tools fail.
  • 23 checks are deliberate output or exit-status differences: 6 deliberate errors, 3 with different output and 14 -nogap checks with a non-standard genetic code.

Some of the differences, as measured against PAL2NAL v14:

  • An invalid character in the protein alignment is an error. PAL2NAL treats it as X, and its output can lose a codon without saying so.
  • . is read as a gap. In PAL2NAL it misaligns the output row.
  • In code 10, TGA is cysteine, as in the current NCBI table. PAL2NAL treats it as a stop.
  • In mitochondrial data, PAL2NAL's -nogap deletes real tryptophan (TGA) columns, because it always uses the standard code's stops.
  • Probably-wrong data, such as unrelated DNA or a gene where most codons do not match, gets a notice on stderr. With --strict it is an error.
  • Any error gives a non-zero exit status. PAL2NAL always exits with 0.

The full list is in the README and tests/README.md.

Speed

Genes × codonsPAL2NAL v14COALPAL2NAL ÷ COAL
10 × 5000.051 s0.061 s0.8×
1,000 × 5002.39 s0.139 s17.3×
10,000 × 50024.7 s0.864 s28.6×
100 × 10,00024.5 s0.207 s118.6×

On tiny inputs both tools take about 0.05 s, nearly all of it start-up, and COAL is slightly slower. As genes get longer, PAL2NAL's time grows much faster than their length. COAL's grows in proportion to the input.

Half a million genes of 500 codons (974 MB of input) took 9.8 s with 4 processes and 25.2 s with 1. The 1-process run used at most 131 MB of memory. We did not run PAL2NAL at that size.

Measured on one Windows 11 machine: Intel 64-bit CPU (Family 6 Model 183), Python 3.13.9, Strawberry Perl 5.42.3. Raw data and the command to reproduce them are in the README.

Limitations

  • COAL does not read Gblocks-format input or write PAL2NAL's -html web-server output.
  • coal writes FASTA unless you ask for another format. The pal2nal command defaults to CLUSTAL, as PAL2NAL does.
  • The Windows installer is not code-signed. SmartScreen asks you to confirm, and Smart App Control blocks it outright.
  • COAL is not on PyPI. Install it from the release with the commands on this page.
  • More than 4 processes do not help yet, because one main process reads and writes everything.

If Smart App Control blocks COAL

Smart App Control on Windows 11 blocks unsigned apps. It has no Run anyway button and no way to allow a single app. You can switch it off, but on some Windows versions it can then only be switched back on by resetting or reinstalling Windows. We suggest leaving it on and installing with pip instead. In PowerShell, with Python 3.10 or newer from python.org:

py -m venv $HOME\coal-env & $HOME\coal-env\Scripts\python -m pip install "coal[gui] @ https://github.com/plumat-coal/COAL/releases/latest/download/coal_src.tar.gz" & $HOME\coal-env\Scripts\python -m coal_app

The last line starts the app. Open http://127.0.0.1:7860 in your browser. The app listens on this computer only.

To run COAL without installing it, unzip COAL-windows-x64.zip and run COAL\COAL.exe. Windows asks for the same confirmation. On a managed university or company computer, IT policy may block both.

macOS

  1. In Terminal, run python3 --version. You need 3.10 or newer. If yours is older, install the current Python from python.org.
  2. Make a virtual environment for COAL:
    python3 -m venv ~/coal-env
  3. Install COAL and its app into it:
    ~/coal-env/bin/python -m pip install "coal[gui] @ https://github.com/plumat-coal/COAL/releases/latest/download/coal_src.tar.gz"
  4. Start the app and open http://127.0.0.1:7860 in your browser. Ctrl+C in Terminal stops it.
    ~/coal-env/bin/coal-gui

Linux

  1. Run python3 --version (3.10 or newer). On Debian and Ubuntu you may also need sudo apt install python3-venv.
  2. Recent Debian, Ubuntu and Fedora refuse pip install outside a virtual environment, so make one and install COAL into it:
    python3 -m venv ~/coal-env ~/coal-env/bin/python -m pip install "coal[gui] @ https://github.com/plumat-coal/COAL/releases/latest/download/coal_src.tar.gz"
  3. Start the app with ~/coal-env/bin/coal-gui and open http://127.0.0.1:7860. On a server, use the command line.

Command line only

The pip install also puts coal and pal2nal in ~/coal-env/bin ($HOME\coal-env\Scripts on Windows). For the command line alone, write coal instead of coal[gui] in the install command. The engine has no required dependencies.

coal protein.aln.fasta dna.fasta -o codon.aln.fasta
coal protein.aln.fasta dna.fasta -codontable 2 -nogap -o codon.aln.fasta
coal --help

Check a file

Download SHA256SUMS.txt into the same folder as the file, then run the command for your system.

Windows (PowerShell)
Get-FileHash .\COAL-Setup-windows-x64.exe -Algorithm SHA256
The hash must equal the one on that file's line of SHA256SUMS.txt. Case does not matter.
Linux
sha256sum -c --ignore-missing SHA256SUMS.txt
Every file you downloaded should print OK.
macOS
shasum -a 256 coal_src.tar.gz
Compare the result with that file's line of SHA256SUMS.txt.
