How it works

A protein alignment lines up the amino acids of related genes, one letter each. A codon alignment is the same picture written in DNA: three bases under each amino acid, and --- under each gap. COAL writes it from the protein alignment and the coding DNA (unaligned), and checks that each codon really codes for the letter above it. The animation below takes about twenty seconds:

Running COAL

COAL takes two files: the protein alignment (FASTA or CLUSTAL) and the coding DNA of the same genes (FASTA, not aligned). Sequences are paired by name. The examples below are in the examples/ folder of the repository and under Try an example in the app. The clean example has 8 genes:

$ coal examples/clean/protein.aln.fasta examples/clean/dna.fasta -o codon.aln.fasta
$ echo $?
0
$ head -3 codon.aln.fasta
>gene01
ATG---GCGAGG---CCTTCCACTACTACCGTGAATATGTGGGGCTCGACACCAGTTTGG
AATGGAGGG---AAAATG---TGGTTTGCTATGGGCGCCGTTGATAATATGCCTACCATG

An exit status of 0 means every gene fitted. The output is the codon alignment:

The options are PAL2NAL's. The ones most people need:

  • -codontable 2 chooses the genetic code, by its NCBI number: 1 is the standard code and the default, 2 vertebrate mitochondrial, 4 mould and protozoan mitochondrial, 11 bacteria and plastids.
  • -output clustal, paml or codon chooses the output format; coal writes FASTA unless told otherwise. paml is what PAML's codeml reads.
  • -nogap removes every column that has a gap or a stop codon, which some dN/dS programs need.
  • --keep-going leaves out any gene that cannot be converted and writes the rest.

The pal2nal command, installed with COAL, takes a PAL2NAL command line exactly as it is, and writes CLUSTAL by default as PAL2NAL does. Large inputs are split across CPU cores automatically (each extra process needs about 4 million bases of DNA to pay for its start-up); -j 2 limits it to two processes.

Warnings and errors

COAL checks that the DNA spells the protein. Two kinds of message matter for the output. (A third, a notice, flags data that is probably wrong, such as DNA from a different gene; --strict turns it into an error.)

A warning: the gene fits, but some codons do not match

The alignment is still written. The usual cause is the wrong genetic code. The mito example has 24 mitochondrial genes; with the standard code, COAL warns about each codon that does not match and then says which code would fit:

$ coal examples/mito/protein.aln.fasta examples/mito/dna.fasta -o codon.aln.fasta
coal: warning: Homo_COX1 pepAlnPos 1: M does not correspond to ATA
coal: warning: Homo_COX1 pepAlnPos 7: M does not correspond to ATA
coal: warning: Homo_COX1 pepAlnPos 36: W does not correspond to TGA
(176 more warnings, 179 in all)
coal: summary: 24 of 24 sequences have codons that do not match their amino acid (kept in the alignment). Under genetic code 2 (Vertebrate mitochondrial), all 24 sequences match their protein; under code 1, none do. Codes 5 and 13 fit these sequences too: choose the code of the organism and organelle the genes come from. Re-run with -codontable 2.
$ coal examples/mito/protein.aln.fasta examples/mito/dna.fasta -codontable 2 -o codon.aln.fasta
$

pepAlnPos is the column in the protein alignment. The app says the same thing in one line per gene, and offers the re-run as a button:

Homo_COX1: 7 codons do not match their amino acid (first at column 1): the protein says M but the DNA has ATA. Kept in the alignment; check the genetic code.

An error: the gene does not fit at all

Nothing is written and the exit status is 1. In the one_broken_gene example, one gene has lost a base, so from that point on its codons are read out of step:

$ coal examples/one_broken_gene/protein.aln.fasta examples/one_broken_gene/dna.fasta -o codon.aln.fasta
coal: error: OG0001_sp14: protein and DNA are inconsistent (no match found)
coal: summary: OG0001_sp14: Frameshift at column 102: one base is missing in the DNA, so from here on the codons are read out of step.
coal: summary: The run stopped at OG0001_sp14: 6 sequences were not checked and no output was written. Add --keep-going to write the other sequences and leave this one out.
$ echo $?
1

PAL2NAL v14 reports the inconsistency too, but exits with status 0, so a pipeline would carry on. With --keep-going, COAL writes the other 19 genes and leaves this one out, with exit status 2.

A base lost near the end of a gene may not stop the run: the gene still fits, with a few mismatch warnings at the end, and the app points out that the run of mismatches looks like a frameshift.

The C++ engine

COAL has two engines with byte-identical output. The Python engine comes with the pip install and runs anywhere. The C++ engine, coal-cpp, is the fast one: it did a million genes in 12.5 s, where the Python engine takes under a minute and PAL2NAL v14 took 62 min. Both engines take the same options.

  • Windows app: coal-cpp is included, and the app uses it on its own for inputs of 1 MB or more.
  • pip install, any system: build it from the source. You need a C++17 compiler (GCC, Clang or Visual Studio) and CMake 3.16 or newer: 
    git clone https://github.com/plumat-coal/COAL && cd COAL
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build --config Release
export COAL_CPP=$PWD/build/coal-cpp
    On Windows the program is build\Release\coal-cpp.exe. With COAL_CPP set (or coal-cpp on your PATH), coal hands inputs of 1 MB or more to it. You can also run coal-cpp directly, with the same options as coal. COAL_ENGINE=python or COAL_ENGINE=cpp forces one engine.

More, including how to use the engine as a C++ library, in docs/cpp-engine.md.
