Example

The repository's clean example has 8 genes of 140 to 144 codons (plus a stop codon), aligned in 150 columns, with gaps in the protein alignment only.

$ coal examples/clean/protein.aln.fasta examples/clean/dna.fasta -o codon.aln.fasta
$ echo $?
0
$ head -3 codon.aln.fasta
>gene01
ATG---GCGAGG---CCTTCCACTACTACCGTGAATATGTGGGGCTCGACACCAGTTTGG
AATGGAGGG---AAAATG---TGGTTTGCTATGGGCGCCGTTGATAATATGCCTACCATG

PAL2NAL-style options work as they are, for example coal pep.aln nuc.fasta -codontable 2 -o out.fasta. The package also installs a pal2nal command that takes a PAL2NAL command line unchanged. With -nogap, COAL removes the stop codons of the genetic code you chose; PAL2NAL v14 always removes the standard code's.

Large inputs are split across processes automatically. -j sets the maximum.

Warnings and errors

The mito example has 24 vertebrate mitochondrial genes. With the standard genetic code (the default), COAL writes the alignment but warns about every codon that does not match its residue, then suggests a code:

$ coal examples/mito/protein.aln.fasta examples/mito/dna.fasta -o codon.aln.fasta
coal: warning: Homo_COX1 pepAlnPos 1: M does not correspond to ATA
coal: warning: Homo_COX1 pepAlnPos 7: M does not correspond to ATA
coal: warning: Homo_COX1 pepAlnPos 36: W does not correspond to TGA
(176 more warnings, 179 in all)
coal: summary: 24 of 24 sequences have codons that do not match their amino acid (kept in the alignment). Under genetic code 2 (Vertebrate mitochondrial), all 24 sequences match their protein; under code 1, none do. Codes 5 and 13 fit these sequences too: choose the code of the organism and organelle the genes come from. Re-run with -codontable 2.
$ coal examples/mito/protein.aln.fasta examples/mito/dna.fasta -codontable 2 -o codon.aln.fasta
$

The desktop app runs the same engine and gives one line per gene instead of one per codon:

Homo_COX1: 7 codons do not match their amino acid (first at column 1): the protein says M but the DNA has ATA. Kept in the alignment; check the genetic code.

In the one_broken_gene example, 1 of 20 genes is missing a base. The run stops and nothing is written:

$ coal examples/one_broken_gene/protein.aln.fasta examples/one_broken_gene/dna.fasta -o codon.aln.fasta
coal: error: OG0001_sp14: protein and DNA are inconsistent (no match found)
coal: summary: OG0001_sp14: Frameshift at column 102: one base is missing in the DNA, so from here on the codons are read out of step.
coal: summary: The run stopped at OG0001_sp14: 6 sequences were not checked and no output was written. Add --keep-going to write the other sequences and leave this one out.
$ echo $?
1

PAL2NAL v14 reports an inconsistency here too, but exits with status 0, so a pipeline would carry on.

Not every frameshift stops the run. A base missing near the end of a gene can still let the gene fit, with a few mismatch warnings; the app then says the run of mismatches looks like a frameshift.

Limitations

  • COAL does not read Gblocks-format input or write PAL2NAL's -html web-server output.
  • coal writes FASTA unless you ask for another format. The pal2nal command defaults to CLUSTAL, as PAL2NAL does.
  • The Windows installer is not code-signed. SmartScreen asks you to confirm, and Smart App Control blocks it outright.
  • COAL is not on PyPI. Install it from the release with the commands on the Install page.
  • More than 4 processes do not help yet, because one main process reads and writes everything.
