Output and exit status

PAL2NAL is by Suyama, Torrents and Bork (2006). We wrote COAL independently, in Python, and it contains none of PAL2NAL's code: we ran PAL2NAL version 14 as a separate program, only to compare outputs. PAL2NAL is GPL-2.0; COAL is MIT.

COAL's output is identical to PAL2NAL v14's except for a short list of documented, deliberate differences. These are newer NCBI genetic-code tables (codes 3, 10, 11 and 13), -nogap removing the chosen code's stop codons, the chosen code's start codons for the first Met, pairing by IDs that match only after normalising, and inputs where PAL2NAL v14 writes malformed output or fails.

Our test suite compares COAL with stored PAL2NAL v14 output on 39 input cases, with every option combination in all 4 output formats: 285 checks.

  • Standard output is byte-identical in 238 checks. In 4 of these the warnings differ on purpose (NCBI tables 10, 11 and 13).
  • Of the rest, in 24 both tools fail.
  • 23 checks are deliberate output or exit-status differences: 6 deliberate errors, 3 with different output and 14 -nogap checks with a non-standard genetic code.

Some of the differences, as measured against PAL2NAL v14:

  • An invalid character in the protein alignment is an error. PAL2NAL treats it as X, and its output can lose a codon without saying so.
  • . is read as a gap. In PAL2NAL it misaligns the output row.
  • In code 10, TGA is cysteine, as in the current NCBI table. PAL2NAL treats it as a stop.
  • In mitochondrial data, PAL2NAL's -nogap deletes real tryptophan (TGA) columns, because it always uses the standard code's stops.
  • Probably-wrong data, such as unrelated DNA or a gene where most codons do not match, gets a notice on stderr. With --strict it is an error.
  • Any error gives a non-zero exit status. PAL2NAL always exits with 0.

The full list is in the COAL documentation and tests/README.md.

On tiny inputs both tools take about 0.05 s, nearly all of it start-up, and COAL is slightly slower. As genes get longer, PAL2NAL's time grows much faster than their length. COAL's grows in proportion to the input.

Half a million genes of 500 codons (974 MB of input) took 9.8 s with 4 processes and 25.2 s with 1. The 1-process run used at most 131 MB of memory. We did not run PAL2NAL at that size.

Measured on one Windows 11 machine: Intel 64-bit CPU (Family 6 Model 183), Python 3.13.9, Strawberry Perl 5.42.3. Raw data and the command to reproduce them are in the benchmark results.
