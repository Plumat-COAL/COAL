In short

  • A PAL2NAL command line works as it is, and the output is the same.
  • A gene that does not fit is an error with exit status 1, naming the gene and the column, so a pipeline stops.
  • A million genes take 12.5 s and 172 MB of memory; PAL2NAL v14 took 62 min and 18.6 GB on the same machine.
  • Genetic codes follow the current NCBI tables, and when the genes fit another code better, COAL says which.
  • There is an app for people who do not use a terminal, with the alignment on screen and the problems marked.

Compared with PAL2NAL

PAL2NAL is by Suyama, Torrents and Bork (2006). We wrote COAL independently, in Python and C++, and it contains none of PAL2NAL's code: we ran PAL2NAL v14 as a separate program, only to compare outputs. PAL2NAL is GPL-2.0; COAL is MIT.

COAL's output is identical to PAL2NAL v14's except for a short list of documented, deliberate differences. These are newer NCBI genetic-code tables (codes 3, 10, 11 and 13); -nogap removing the chosen code's stop codons; the chosen code's other start codons (such as TTG and CTG) accepted for the first Met; sequences paired by name even when the names differ only in case, a version suffix or a database prefix; and inputs where PAL2NAL v14 writes malformed output or fails.

Our test suite compares COAL with stored PAL2NAL v14 output on 39 input cases, with every option combination in all 4 output formats: 285 checks.

  • Standard output is byte-identical in 238 checks. In 4 of these the warnings differ on purpose (NCBI tables 10, 11 and 13).
  • Of the rest, in 24 both tools fail.
  • 23 checks are deliberate output or exit-status differences: 6 deliberate errors, 3 with different output and 14 -nogap checks with a non-standard genetic code.

Some of the differences:

  • An invalid character in the protein alignment is an error. PAL2NAL treats it as X, and its output can lose a codon without saying so.
  • . is read as a gap. In PAL2NAL it misaligns the output row.
  • In code 10, TGA is cysteine, as in the current NCBI table. PAL2NAL treats it as a stop.
  • In mitochondrial data, PAL2NAL's -nogap deletes real tryptophan (TGA) columns, because it always uses the standard code's stops.
  • Probably-wrong data, such as unrelated DNA or a gene where most codons do not match, gets a notice on stderr. With --strict it is an error.
  • Any error gives a non-zero exit status. PAL2NAL always exits with 0.

The full list is in docs/differences.md and tests/README.md.

Speed

1,000 × 10,000280 s0.251 s1,115×

Every COAL output in these runs matched PAL2NAL v14's or the simulated truth. On tiny inputs both tools take a few hundredths of a second, nearly all of it start-up. As genes get longer, PAL2NAL's time grows much faster than their length; COAL's grows in proportion to the input. PAL2NAL v14 cannot process proteins longer than about 22,000 residues (Perl's limit on capture groups in one regex); COAL can.

At a million genes PAL2NAL v14 needed 18.6 GB of memory and COAL 172 MB. COAL's Python engine gives the same output more slowly: under a minute at a million genes (74× faster than PAL2NAL v14), and slower than PAL2NAL on many tiny files run one process at a time. How to get the C++ engine.

Measured on one Windows 11 machine (Intel i5-13600KF, 32 GB), COAL commit 47f57f1; the million-gene PAL2NAL run is a single run. Raw data and the method are in the benchmark results.
